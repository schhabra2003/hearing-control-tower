- Why an 80-row copy: the upload route to Google Drive takes about 3.1 MB a call, and the 1,200-row sheet is 14.7 MB. The copy is built by the same generator with END = 80 (the same formulas on every row, all 18 tabs, the same example); 2.9 MB.
- Method: upload the .xlsx to Google Drive with conversion to Google Sheets (Google recalculates everything), export it again as .xlsx, compare every filled cell with the LibreOffice 24.2 result of the same file (a comparison script, not published).
- Run A, the sheet as it stood on 21 Nov 2026 before fix 3 (generator md5 e1c472f2), 39,573 formulas: all formulas kept, but 2 faults that only Google Sheets shows:
  1. Calendar tab: 62 unused rows (19 to 80) were filled with text, and 7 cells of column J held #REF!. Cause: Google Sheets reads INDEX(range,"") as INDEX(range,0), the whole column; Excel and LibreOffice give an error value that the IFERROR turns into an empty cell. The empty text comes from column F of the Calendar file tab, which the Calendar tab had read since an earlier fix.
  2. Dockets A1 read "A CELL OF THE HEARINGS, OFFICES OR BENCH TAB SHOWS AN ERROR VALUE" on a clean sheet. Cause (found with a probe copy that split A1 into 21 parts): NOT(ISBLANK(Hearings!DA2:DA80)) gives #VALUE! because the converted tab ends at its last used column, CZ, so column DA does not exist.
- Fix 3 (4 exact replacements in the sheet generator): a helper column S on the Calendar file tab (= F, or 9999999 when there is no event; INDEX of that row is an error value in all three programs) that the Calendar tab reads; a heading in Hearings DA1 so that the column exists.
